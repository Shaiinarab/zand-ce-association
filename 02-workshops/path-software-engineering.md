# مسیر مهندسی نرم‌افزار و برنامه‌نویسی

**شناسه مسیر:** SE · **سطح:** مقدماتی تا پیشرفته · **وضعیت:** طرح آموزشی

## هدف

تبدیل دانشجو از مصرف‌کننده کد به سازنده نرم‌افزار قابل نگه‌داری. این مسیر زبان‌محور نیست؛ مفاهیم برنامه‌نویسی، طراحی، ساخت، آزمون، انتشار و کار تیمی را با چند پروژه پیوسته آموزش می‌دهد.

## نقشه یادگیری

| مرحله | موضوع‌ها | تمرین و خروجی قابل ارزیابی |
|---|---|---|
| ۱. مبانی برنامه‌نویسی | الگوریتم، متغیر، شرط، حلقه، تابع، ساختار داده، خطایابی | حل مسئله با توضیح پیچیدگی و تست |
| ۲. ابزار توسعه | Git، خط فرمان، IDE، دیباگر، مدیریت وابستگی | مخزن تمیز با تاریخچه commit و README |
| ۳. توسعه وب | HTML، CSS، JavaScript/TypeScript، دسترس‌پذیری و طراحی واکنش‌گرا | رابط وب قابل استفاده روی موبایل و دسکتاپ |
| ۴. Backend و API | HTTP، REST، اعتبارسنجی ورودی، احراز هویت، مدیریت خطا | API مستند با چند endpoint و تست |
| ۵. داده | SQL، مدل‌سازی، طراحی schema، migration و پشتیبان‌گیری | پایگاه داده با queryهای قابل توضیح |
| ۶. مهندسی کیفیت | تست واحد و یکپارچه، lint، CI، code review | pipeline خودکار و گزارش تست |
| ۷. طراحی سیستم | ماژولار بودن، معماری، امنیت پایه، مشاهده‌پذیری و کارایی | سند تصمیم معماری و نمونه قابل اجرا |
| ۸. پروژه تیمی | issue، branch، pull request، review و انتشار | محصول کوچک با نسخه قابل استفاده و مستندات |

## شاخه‌های انتخابی

- **Frontend:** رابط کاربری، state، دسترس‌پذیری و performance
- **Backend:** API، پایگاه داده، صف، cache و طراحی سرویس
- **Mobile:** مبانی Android یا توسعه چندسکویی
- **Systems Programming:** حافظه، پردازه، فایل، هم‌زمانی و زبان‌های سطح پایین
- **Data & Automation:** پردازش داده، اسکریپت‌نویسی و pipeline

## فناوری‌های پیشنهادی

هسته وب با HTML، CSS، JavaScript و TypeScript آغاز می‌شود. برای Backend یک زبان و چارچوب متناسب با مدرس انتخاب می‌شود؛ برای پایگاه داده SQL و PostgreSQL یا SQLite کافی است. Git و ابزارهای متن‌باز اولویت دارند. هیچ زبان یا IDE خاصی پیش‌نیاز اجباری نیست.

## پروژه نهایی

یک سامانه کوچک واقعی، مانند سامانه ثبت رویداد انجمن، شامل رابط، API، پایگاه داده، تست، CI، مستندات و نسخه منتشرشده.

## ارزیابی

کیفیت حل مسئله، خوانایی و نگه‌داری کد، تست‌پذیری، مستندات، امنیت پایه و مشارکت در بازبینی کد ارزیابی می‌شوند؛ تعداد خطوط کد معیار موفقیت نیست.

## پیش‌نیاز و ایمنی

آشنایی عمومی با رایانه کافی است. داده واقعی دانشجو، رمز عبور، کلید API یا اطلاعات خصوصی نباید در مخزن عمومی یا سرویس آزمایشی قرار گیرد. کلیدها با متغیر محیطی و secretهای امن مدیریت شوند.
