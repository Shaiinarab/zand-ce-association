# مسیر اینترنت اشیا و سیستم‌های نهفته

**شناسه مسیر:** IOT · **سطح:** مقدماتی تا پیشرفته · **وضعیت:** طرح آموزشی

## هدف

اتصال نرم‌افزار به جهان فیزیکی؛ از خواندن سنسور و کنترل خروجی تا انتقال داده، پایش، امنیت و طراحی یک نمونه IoT قابل تکرار.

## نقشه یادگیری

| مرحله | موضوع‌ها | تمرین و خروجی |
|---|---|---|
| ۱. الکترونیک پایه | ولتاژ، جریان، مقاومت، مدار، زمین مشترک و دیتاشیت | مدار LED با محاسبه مقاومت |
| ۲. میکروکنترلر | GPIO، ورودی/خروجی، ADC، PWM و وقفه | برنامه خواندن ورودی و کنترل خروجی |
| ۳. برد و سنسور | Arduino، ESP32، دما، نور، فاصله و کالیبراسیون | ثبت داده سنسور با timestamp |
| ۴. ارتباط | UART، I²C، SPI، Wi-Fi و BLE | انتخاب پروتکل و تبادل داده |
| ۵. پیام‌رسانی | MQTT، topic، broker، QoS و reconnect | ارسال داده به broker آزمایشگاهی |
| ۶. Backend و داشبورد | ذخیره‌سازی سری زمانی، API و visualization | داشبورد داده سنسور |
| ۷. امنیت دستگاه | هویت دستگاه، به‌روزرسانی، secrets و شبکه‌بندی | threat model و تنظیم امن نمونه |
| ۸. پروژه یکپارچه | مصرف انرژی، پایداری، خطا و مستندسازی | نمونه IoT با گزارش آزمون |

## ابزارهای پیشنهادی

ESP32 و Arduino برای شروع؛ PlatformIO یا Arduino IDE برای توسعه؛ MQTT و یک broker محلی برای آزمایش؛ و ابزارهای ساده ثبت و نمایش داده. انتخاب قطعات باید براساس موجودی واقعی آزمایشگاه و دیتاشیت سازنده باشد.

## پروژه نهایی

یک سامانه پایش محیط آزمایشگاه که داده سنسور را به‌صورت محلی ارسال و نمایش دهد، قطع ارتباط را مدیریت کند و راه‌اندازی آن مستند باشد. ارسال داده به اینترنت عمومی برای پروژه پایلوت ضروری نیست.

## ایمنی سخت‌افزار و داده

تمرین‌ها با ولتاژ پایین و منبع تغذیه محدودشده انجام می‌شوند. اتصال مستقیم برق شهر، باتری آسیب‌دیده یا بار پرجریان در فعالیت دانشجویی مجاز نیست. قطبیت، جریان مجاز پایه‌ها، سطح ولتاژ و دیتاشیت باید پیش از اتصال بررسی شوند. اطلاعات مکانی یا داده شخصی کاربران بدون ضرورت و رضایت جمع‌آوری نشود.
