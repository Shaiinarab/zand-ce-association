# مسیر بازی‌سازی و طراحی تجربه تعاملی

**شناسه مسیر:** GAME · **سطح:** مقدماتی تا پیشرفته · **وضعیت:** طرح آموزشی

## هدف

ساخت بازی‌های کوچک اما کامل؛ از ایده و حلقه اصلی بازی تا ورودی، فیزیک، رابط، صدا، ذخیره‌سازی، تست و انتشار. هدف، یادگیری فرایند تولید است، نه جمع‌کردن فهرستی از موتورهای بازی.

## نقشه یادگیری

| مرحله | موضوع‌ها | تمرین و خروجی |
|---|---|---|
| ۱. طراحی بازی | core loop، مکانیک، قوانین، بازخورد، تعادل و نمونه‌سازی | سند یک‌صفحه‌ای طراحی بازی |
| ۲. مبانی موتور | صحنه، node/object، component، resource و چرخه اجرا | صحنه تعاملی کوچک |
| ۳. اسکریپت و ورودی | حرکت، کنترل، state machine و رویدادها | شخصیت قابل کنترل با ورودی صفحه‌کلید |
| ۴. فیزیک و برخورد | collision، rigid/static body، raycast و محدودیت‌ها | مرحله‌ای با برخورد و تعامل |
| ۵. رابط و روایت | HUD، منو، مرحله، دیالوگ و راهنمای بازیکن | منوی کامل و جریان شروع تا پایان |
| ۶. صدا و جلوه | طراحی صوتی، انیمیشن، ذرات و نور | بازخورد صوتی/بصری هدفمند |
| ۷. ذخیره و تست | save/load، تست بازی‌پذیری، profiling و رفع اشکال | گزارش تست باگ و اصلاح |
| ۸. انتشار | export، کنترل نسخه، مجوز دارایی و صفحه معرفی | نسخه قابل اجرا و صفحه پروژه |

## ابزارها

Godot گزینه پیش‌فرض سبک و متن‌باز برای پایلوت است. Unity می‌تواند مسیر جایگزین یا تخصصی باشد، مشروط به دسترسی و سخت‌افزار مناسب. برای هنر دوبعدی می‌توان از ابزارهای آزاد و برای صدا از نرم‌افزارهای متن‌باز استفاده کرد. هیچ دارایی بدون مجوز روشن وارد پروژه نشود.

## شاخه‌های تخصصی

- بازی دوبعدی و پلتفرمر
- بازی سه‌بعدی و نورپردازی
- طراحی مرحله و روایت تعاملی
- Multiplayer و همگام‌سازی
- ابزارسازی، shader و بهینه‌سازی

## پروژه نهایی

یک بازی کوچک با حلقه اصلی روشن، حداقل یک مرحله، منو، صدا، صفحه راهنما، کنترل نسخه و فایل اجرایی. بازی باید توسط فردی خارج از تیم سازنده آزمایش شود.

## ارزیابی و ایمنی

بازی‌پذیری، وضوح هدف، پایداری، دسترس‌پذیری کنترل‌ها، کیفیت فنی و رعایت مجوزها ارزیابی می‌شوند. استفاده از assetهای دارای مجوز نامشخص یا کپی محتوای بازی‌های تجاری مجاز نیست. برای Multiplayer، ارتباطات و داده کاربران باید با حداقل‌سازی داده و کنترل دسترسی طراحی شوند.
