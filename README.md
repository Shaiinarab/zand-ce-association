# بسته آغاز کار انجمن علمی مهندسی کامپیوتر زند
نسخه ۰٫۱ — ۲۰۲۶-۱۱-۱۶

وضعیت: پیش‌نویس پیشنهادی؛ نه سند مصوب مؤسسه و نه ادعای وابستگی رسمی به ACM یا IEEE.
دبیر بر اساس اعلام خود او: شاهین عرب. نام رسمی انجمن، استاد مشاور، اعضای شورا و مسیر مجوز باید تأیید شوند.

## شروع سریع
1. اسناد 00-governance را با شورا و استاد مشاور بررسی کنید.
2. مسئول و تاریخ معارفه را در 01-orientation مشخص کنید.
3. فقط دو کارگاه اول را قطعی کنید؛ ادامه وابسته به ارزیابی باشد.
4. برای پادکست، قبل از ضبط/انتشار رضایت و مجوز را تعیین کنید.
5. داده اعضا و رضایت‌نامه‌ها را خارج از این مخزن عمومی نگه دارید.

## ساختار
- 00-governance: منشور، تقسیم کار، نقشه راه و ثبت تصمیم
- 01-orientation: برنامه معارفه و متن ارائه
- 02-workshops: نقشه آموزشی، ایمنی و طرح دو کارگاه
- 03-podcast: پایلوت پادکست و چک‌لیست رضایت
- 04-alumni-mentoring: شبکه و منتورینگ و گردهمایی
- 05-operations: فرم‌ها، شاخص‌ها، حریم خصوصی و تداوم فعالیت
- 06-research: منابع، حدود شواهد و پرسش‌های باز
- .github/ISSUE_TEMPLATE: فرم پیشنهاد فعالیت و گزارش

## انتشار
این بسته محلی و آماده ورود به Git است؛ در GitHub منتشر نشده و git history ندارد.
پیش از انتشار: تعیین مالک سازمانی، بازبینی اطلاعات، تأیید لوگو و نام، تعیین مجوز محتوای متعلق به انجمن.
هیچ مجوزی برای تصویر، صدای استادان یا محتوای شخص ثالث به صورت خودکار اعطا نمی‌شود.
لینک‌های Bootcraft و Workshop Zero اکنون در دسترس‌اند و محتوای هر دو در مخزن‌های جدا نگه‌داری می‌شود؛ این بسته فقط دروازه و اسناد انجمن را نگه می‌دارد.

## پورتال (نسخه ۰٫۲)

همین بسته حالا یک پورتال Next.js قابل اجرا و قابل استقرار است:

```bash
npm install
npm run dev      # http://localhost:3000
npm run build    # خروجی ایستا در out/
```

- `/` — صفحه فرود با زنجیره بوت، برنامه‌ها، دیوار خروجی و فرم عضویت
- `/docs` — نقشه جست‌وجوپذیر همه سندها
- `/docs/<حوزه>/<سند>` — نمایش Markdown با فهرست بخش‌ها و ناوبری قبلی/بعدی
- `/roadmap` — نقشه راه ۹۰ روزه به شکل دروازه‌های قابل عبور
- `/terminal` — ترمینال محلی برای گشتن در سندها (`ls`, `open`, `status`)

استقرار: `vercel.json` برای Vercel و `.github/workflows/pages.yml` برای GitHub Pages آماده است. هیچ کلید یا سرویس پشتیبان لازم نیست؛ خروجی کاملاً ایستا است. مشخصات ساخت در `docs/hub-build-spec.md` نگه‌داری می‌شود.
